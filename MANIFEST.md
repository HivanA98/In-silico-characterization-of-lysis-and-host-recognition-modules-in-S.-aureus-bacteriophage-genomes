repository that produced or reproduce it. It was generated by reorganising the
original working repository into a fixed layout for archival and review; no data or
code file was modified in the process (see "Files intentionally left out" at the
end for what was left behind and why).

## 2. Not yet deposited

- **Table II (combined) and Table III (combined).** As printed, Table II joins S2's
  holin/RBP columns with S4+InterPro's endolysin columns, and Table III joins the
  Table II-style output of all three annotation arms. No single merged CSV for either
  exists in the repository; each would need to be assembled by joining the listed
  source files on genome accession. This was left undone rather than guessed at,
  since assembling it is a data-combination step, not a filing step.
- **Supplementary Table S2 (phage-vs-host codon usage).** `S7b_phage_codon_usage.py`
  writes `phage_codon_usage.csv`, `phage_host_rscu_matrix.csv` and
  `phage_host_similarity.csv` to its `--output_dir`. None of the three exist anywhere
  in the repository — only S7's host-side tables (`analysis/codon/`) are present.
  Would need `S7b_phage_codon_usage.py --phage-dir data\genomes_deposited --host
  data\host_genomes -o <dir> --profile code\profiles\AureusPhage.yaml` to be run.
- **Supplementary Table S4, the identity numbers.** `S4b_endolysin_domain_identity.py`
  writes `identity_matrix_<domain>.csv` and `identity_summary_<label>.csv` after the
  per-domain alignments are read back in (`--align read`). Neither file exists
  anywhere in the repository; only the domain-boundary CSV and the MAFFT-aligned
  FASTA files are present in `analysis/alignments/endolysin_domains/`. Would need the
  script re-run with `--align read` over the existing alignments.
- **Supplementary Table S1, full 22-genome coverage.** The deposited
  `results/arm4_phynteny/` output covers only genome EU418428 (A5W): `Table1_AureusPhage.csv`
  and `Table2_holin_rbp_AureusPhage.csv` each hold one data row, and the source file
  recorded in `Table1_AureusPhage.csv` is `GenBank\Phynteny\phynteny.gbk` itself,
  which is the *un-split*, all-22-genomes-in-one-file Phynteny export. Consistent with
  the "one genome per file" limitation already documented in `ARCHITECTURE.md`
  and `README.md`, running a stage script directly against that file only yields the
  first record. Would need `data/genomes_phynteny/phynteny.gbk` split into one file
  per genome and S1/S2/S4 re-run on the resulting 22 files to cover the full set.
- **InterPro annotation of the TerL sequences** (`analysis/interpro/terl/`). No
  InterPro submission for the terminase sequences exists in the repository — Figure 1
  is built from the MAFFT alignment and MEGA tree directly, without a domain call.
  Would need `analysis/alignments/terl/TerL_combined_AureusPhage.faa` submitted to
  InterPro if a domain-level check is wanted.
- **MEGA session file (`.mtsx`) and vector figure (`.svg`) for Figure 1.** Git history
  shows `Mega Pyhlogeny.mtsx` and `Mega Pyhlogeny.svg` were previously tracked under
  `Mega Phylogeny Result/` and have since been deleted from the working tree — they no
  longer exist on disk. `analysis/phylogeny_mega/` currently holds a Newick tree, two
  distance-matrix CSVs, a text analysis summary, and a PDF export of the tree, but no
  `.mtsx` session and no `.svg`. Would need the MEGA session re-opened and re-exported
  in both formats if the reviewer needs the editable session or a vector figure.

## 3. Reading order for a referee

1. `README.md` — the method: what each stage does and the exact commands used.
2. `MANIFEST.md` (this file) — to find which file backs a specific number or figure.
3. `results/arm1_deposited/` — the deposited-annotation results Tables I and II rest on.
4. `results/arm2_pharokka/`, `results/arm3_phold/`, `results/arm4_phynteny/` — the
   re-annotation arms that feed Table III and Supplementary Table S1.
5. `analysis/` — the phylogeny (alignments and MEGA export), InterPro output, VIRIDIC
   similarity, and the manuscript-facing codon-usage copy.
6. `manuscript_tables/` — the exact numbers printed in each table, without opening code.
7. `code/` and `ARCHITECTURE.md` — only if you need to see how a number was computed.
