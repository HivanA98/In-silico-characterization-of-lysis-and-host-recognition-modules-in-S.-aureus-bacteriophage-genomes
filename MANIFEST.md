# MANIFEST — MIOC-2026-0245 supplementary repository

This file maps every table and figure in the manuscript to the file(s) in this
repository that produced or reproduce it. It was generated by reorganising the
original working repository into a fixed layout for archival and review, then
updated across two audit passes to close the gaps found after reorganisation
(see git log). No data or code file was modified in any pass (see "Files
intentionally left out" at the end for what was left behind and why).

### Notes on the rows above

- **Table II and Table III (as printed)** were supplied directly by the
  corresponding author as `Table2_REVISED.csv` and
  `Table3_annotation_source_comparison.csv` — these are manuscript-ready,
  not a mechanical join of the arm output performed during this repository
  pass. `Table3_annotation_source_comparison.csv`'s RBP-locus-count column
  was cross-checked against an independent join of
  `results/arm{1,2,3}_*/Table2_holin_rbp_AureusPhage.csv` on genome
  accession during this pass; all 22 rows matched.
- **Table II — endolysin calls for 4 of 22 genomes.** `Table_II_lysis_host_recognition.csv`
  reports MN045228.1, MN336262.1, MN336263.1 and NC_019726.1 without a
  confirmed free-endolysin call. This was checked directly against the
  underlying `endolysin_audit_AureusPhage.csv` in all four annotation arms
  (`arm1_deposited`, `arm2_pharokka`, `arm3_phold`, `arm4_phynteny`): none of
  the four arms has a `Selected=Yes` row for any of these four accessions —
  only keyword-scan candidate rows below the selection threshold. Because the
  gap is identical across all four independently-run arms, it is not a
  stale/outdated result file; it reflects the `S4_endolysin_extractor.py`
  selection rule as currently written. This was raised in the manuscript
  revision correspondence as an open item for the corresponding author to
  confirm the intended selection rule before any "N of 22 confirmed
  endolysins" figure is quoted in the text — it is not corrected here, since
  this repository pass does not edit already-deposited result files.
- **Supplementary Table S1** — reports residual proteins of unknown function
  and their PHROG category assignment; that is a Phynteny/Phold product, not
  an S1–S4 arm output. Neither `phynteny.tsv` (Phynteny's per-CDS table) nor
  the Phold per-genome function counts are in the repository, so the true
  source cannot be regenerated here. `results/arm4_phynteny/` (S1–S4 run on
  the Phynteny-annotated genomes, now the full 22-genome run — see "Gap 1"
  history in the git log) is a separate, legitimate artefact in its own
  right and does not feed Supplementary Table S1.
- **Supplementary Table S4** — two variants exist: `endolysin_identity_all`
  (all 11 unique confirmed endolysins, no status filter) and
  `endolysin_identity_canonical` (8 sequences, `status=free-endolysin` only —
  the "canonical" set the reviewer's question was about). The manuscript
  table is assumed to be the canonical variant; please confirm against the
  typeset PDF, which was not available in this repository to check against.
- **Figure 1 — TerL InterPro domain call.** `analysis/interpro/terl/TerL_combined_AureusPhage.tsv`
  covers 19 of the 20 sequences in `TerL_combined_AureusPhage.faa` (58
  domain-hit rows, no header, standard 15-column InterPro TSV format). The
  tree itself does not depend on this file (built from the MAFFT alignment
  and MEGA directly); it is deposited for readers who want a domain-level
  check. The one sequence with
  no rows, `NC_007021.1_Twort`, is also the shortest sequence in the file
  (286 aa, versus 402–605 aa for the other 19) — consistent with it falling
  below the significance threshold for every member database searched,
  rather than a submission error, but this was not independently confirmed
  by re-running InterProScan and should be checked against the typeset
  figure/legend if a domain call for Twort's TerL is needed.

## 3. Reading order for a referee

1. `README.md` — the method: what each stage does and the exact commands used.
2. `MANIFEST.md` (this file) — to find which file backs a specific number or figure.
3. `results/arm1_deposited/` — the deposited-annotation results Tables I and II rest on.
4. `results/arm2_pharokka/`, `results/arm3_phold/`, `results/arm4_phynteny/` — the
   re-annotation arms that feed Table III and Supplementary Table S1.
5. `analysis/` — the phylogeny (alignments and MEGA export), InterPro output,
   VIRIDIC similarity, endolysin domain-identity matrices, and the
   manuscript-facing codon-usage copy.
6. `manuscript_tables/` — the exact numbers printed in each table, without opening code.
7. `code/` and `ARCHITECTURE.md` — only if you need to see how a number was computed.

## Files intentionally left out

`archive/pre_reorg_leftovers/` and `archive/superseded_drafts/` hold material
that predates or was superseded by the current layout and is not cited by any
manuscript object: an older backup of `code/profiles/AureusPhage.yaml`
(`phage_characterization/`), a code-documentation Word file with no current
home in the fixed layout (`Supplementary_Code_Documentation.docx`), a stray
duplicate FASTA (`endolysin_candidates_tblastn.faa`, byte-identical to
`results/arm1_deposited/endolysin_candidates_AureusPhage.faa`), four CSVs
(`New_Table_pre_reorg_drafts/`) that use an older, incompatible
table-numbering scheme and were not used to fill any Supplementary Table
above, and the superseded single-genome `results/arm4_phynteny/` run
(`arm4_phynteny_single_genome_run/`, replaced by the full 22-genome run
described under Gap 1 in the git log). Everything else found outside the
fixed layout during the reorganisation pass (`GenBank/`, `host/`, a duplicate
root-level `phagecore/` holding only compiled cache files, and a verified
byte-identical duplicate of all of `results/arm1_deposited/` under a folder
named `Supplementary Files/`) was empty or fully redundant and was removed
from the working tree rather than archived.
